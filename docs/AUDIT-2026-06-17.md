## 🟠 High — реальные баги в написанном коде

### H1. Невалидный контент НЕ роняет сборку — «тихий» 404 в проде `[BUG]` — ✅ ИСПРАВЛЕНО 2026-06-17
- **Было:** `src/app/[locale]/lp/[slug]/page.tsx` (`loadLanding`: `try/catch → return null`
  → `notFound()`); `src/app/sitemap.ts` (`safeParse(...).success → continue`).
  Build-скрипт — обычный `next build`, отдельного `validate:content` нет.
- **Почему критично:** прямое нарушение правила CLAUDE.md / §13.1 — «build must fail on invalid
  content». Битый/невалидный JSON лендинга проходил сборку, страница молча отдавала 404,
  slug выпадал из sitemap → замороженный рекламный URL вёл на 404, не ловясь на сборке/CI.
- **Что сделано:**
  1. `scripts/validate-content.ts` — гейт, валидирующий все 176 landing-JSON по той же
     `LandingSchema` (DRY); печатает файл+причину, exit 1 при любой ошибке. Также сверяет
     `slug`/`locale` внутри файла с путём.
  2. `package.json`: `validate:content` (ручной прогон) + `prebuild` (npm запускает его
     автоматически перед `npm run build`) → сборка падает ДО `next build`. Добавлен devDep `tsx`.
  3. `loadLanding` теперь различает ENOENT (→ `null`/404 для несуществующего slug) и битый
     контент (→ `throw` → падает даже прямой `next build`). `sitemap.ts` выровнен (`.parse()`).
- **Проверено (red/green):** чистый репо — `✓ 176 файлов` (exit 0); битый фикстур —
  `✗ … exit 1` с именем файла; `npm run build` с битым фикстуром падает на prebuild; `tsc --noEmit` — 0 ошибок.
- **Примечание:** гейт пока покрывает landings. Demo/quiz-схемы появятся в Sprint 2 — тогда
  добавить их в `validate-content.ts` теми же блоками.

### H2. Обёртка CRM-payload `{ payload: … }` — ✅ ПРОВЕРЕНО 2026-06-17: корректна, правок не требует
- **Файл:** `src/app/api/enroll/route.ts:102` → `body: JSON.stringify({ payload: parsed.data })`.
- **Доказательство по git-истории:** обёртка `{ payload: {...} }` присутствовала с первого дня,
  когда форма постила **напрямую в CRM** (`NEXT_PUBLIC_CRM_WEBHOOK_URL`, до коммита `80ca152`
  «fix CORS: proxy CRM webhook through API route»). Это была реальная рабочая интеграция против
  `crm.soroban.ua`; CORS-прокси лишь перенёс то же тело на сервер. Значит CRM ждёт именно
  конверт `{ payload }`, а описание «плоских полей» в CLAUDE.md относится к содержимому payload.
- **Вывод:** код менять НЕ нужно.

#### H2-bis. Имена внутренних полей — ✅ ПОДТВЕРЖДЕНО 2026-06-17 (живой заявкой)
- Текущие имена payload (`title`, `phones[]`, `comment`, `city`, `source`, `source_information`,
  `utm_*`) проверены сквозной отправкой формы: лид пришёл в `crm.soroban.ua`, **все поля легли
  корректно** (имя, телефон, город, комментарий, UTM). Переименование `full_name→title`,
  `phone→phones[]`, `message→comment` (коммит `a6c6d2b`) — верное.
- **Вывод:** контракт enroll → CRM полностью корректен (конверт `{ payload }` + имена полей).

## 🟡 Medium — латентные риски и локальные дефекты

### M1. CTA-таргеты из JSON игнорируются — ❌ НЕ ПРОБЛЕМА / BY DESIGN (решение 2026-06-17)
- **Суть:** в шаблоне ровно две кнопки с фиксированным поведением — primary открывает форму
  (`EnrollButton`), secondary ведёт на `/demo` (`DemoButton`). Это просто и корректно.
- **Почему изначально пометили как риск:** в JSON у кнопок есть поле `target`, которое код не
  читает. Оно создаёт *иллюзию*, будто кнопками можно управлять из контента, — но по дизайну
  кнопки фиксированы. То есть «лишнее» здесь не код, а декоративное поле `target`.
- **Решение:** НИЧЕГО не делаем. Роутер/расцепление стилей — не нужны (нет требования управлять
  кнопками из контента). Поле `target` оставляем как есть (безвредно; удалять из 176 JSON ради
  косметики не стоит). Если когда-нибудь понадобятся **разные** кнопки на разных лендингах —
  это новая продуктовая фича, проектируется тогда, по реальным требованиям.

### M2. Cookie для UTM и anonymous_id пишутся, но не читаются обратно `[RISK]` — ✅ ИСПРАВЛЕНО 2026-06-17
- **Было:** `src/lib/utm.ts` (`getStoredUtm` читал только `localStorage`);
  `src/lib/anonymous-id.ts` (`getAnonymousId` читал только `localStorage`, иначе генерировал новый id).
  Cookie заявлены как fallback (§6.5, §11.6), но были мертвы → при очистке localStorage
  `anonymous_id` перегенерировался, атрибуция и будущий merge с `user_id` рвались.
- **Что сделано:** в оба модуля добавлен `getCookie()`; `getAnonymousId` и `getStoredUtm` теперь
  читают `localStorage ?? cookie`, а `getAnonymousId` идемпотентно синхронизирует оба носителя.
- **Проверено:** round-trip set→get для anon id и для UTM-JSON со спецсимволами — OK; `tsc` — 0 ошибок.

### M3. `/api/enroll` принимает `http://` для capability-URL с секретом `[RISK]` — ✅ ИСПРАВЛЕНО 2026-06-17
- **Было:** `src/app/api/enroll/route.ts` принимал и `https:`, и `http:` для любого хоста.
  Токен CRM зашит в URL → при ошибочной `http://`-конфигурации секрет ушёл бы открыто.
- **Что сделано:** разрешён только `https:`; `http:` — лишь для loopback (`localhost`/`127.0.0.1`/`[::1]`)
  под локальный мок CRM.
- **Проверено:** https→ACCEPT, http к реальному хосту→REJECT, http к loopback→ACCEPT, ftp→REJECT.

### M4. Юр-страницы захардкожены на украинском для всех 4 локалей `[BUG]` — ⏭️ ОТЛОЖЕНО до Sprint 4 (решение 2026-06-17)
- **Файлы:** `privacy/page.tsx`, `terms/page.tsx`, `cookie-policy/page.tsx` — `metadata.title`
  и текст на украинском без переключения по locale.
- **Эффект:** пользователь `/en`, `/ru`, `/ro` видит украинский на юр-страницах. Смягчено
  `robots: { index: false }` (страницы не индексируются), залинкована прицельно только `/privacy`.
- **Решение:** переводы НЕ делаем сейчас. Реальный юридический текст Privacy + Terms пишет юрист
  в Sprint 4 — тогда же локализуем финальную копию (чтобы не переводить временную болванку дважды).
  При локализации вынести тексты в `src/content/strings/{locale}.json` или per-locale-файлы.
- **`/terms`:** решено ОСТАВИТЬ как noindex-заглушку (спека её предусматривает, юрист — Sprint 4).
  Сейчас не залинкована и исключена из sitemap — корректно, не трогаем.
- **Мелочь рядом (не блокер):** `CookieBanner.tsx` ссылается на `/cookie-policy` без префикса
  локали — работает через redirect прокси; можно поправить на `/{locale}/cookie-policy` заодно
  в Sprint 4.

### M5. `robots.ts` не покрывает `/ro/sign-up` `[BUG]` — ✅ ИСПРАВЛЕНО 2026-06-17
