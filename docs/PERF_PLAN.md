# Производительность: план работ (PLAN)

Диагноз — `PERF_CONCEPT.md`. Цели — `docs/SPECIFICATION.md` §17.

## 🔒 Инварианты URL (НЕ менять — ссылки уже в рекламе)

Ни один этап не должен менять публичные адреса. Что остаётся неприкосновенным:

- **Структуру папок маршрутов** под `src/app/[locale]/…` (сегменты `[locale]/lp/[slug]` и пр. задают URL).
- **Имена JSON-файлов** в `src/content/landings/{locale}/` — это и есть `{slug}` лендинга.
- **`src/proxy.ts`** и `localePrefix: "always"` — префикс локали и редирект `/` → `/{locale}`.
- **Имена ассетов** в `public/` (Этап 5 пережимает картинки *на месте*, без переименований).
- canonical / hreflang / sitemap строятся из `siteUrl/${locale}/…` — формат не трогаем.

Проверка G3 на каждом этапе явно подтверждает доступность `/en|ru|uk|ro/lp/<slug>` по прежним адресам.

## Порядок: архитектурное → локальное

Этапы идут от самого глубокого (рендеринг всего App) к самому поверхностному (конфиг/ассеты). Менять порядок нельзя: пока не починена статика (Этап 1), измерять бандл лендинга (Этап 3) бессмысленно — всё рендерится динамически.

1. **Этап 1 (архитектура).** Статическая генерация / ISR — починить корневой layout.
2. **Этап 2 (архитектура).** Урезать клиентский пейлоад словаря next-intl.
3. **Этап 3 (бандл).** Вес лендинга: убрать framer из пути лендинга, lazy-load формы, убрать дубль `EnrollModal`.
4. **Этап 4 (загрузка/комплаенс).** Consent-gating аналитики (Meta pixel).
5. **Этап 5 (конфиг/ассеты).** AVIF, шрифты, пережатие картинок.
6. **Этап 6 (на будущее).** Зафиксировать требование dynamic-import для демо/квиза.

> Мид-стейдж реплан допустим: если на этапе всплывает архитектурный нюанс, выносим его выше и пересобираем порядок.

## Этап 1 — Статическая генерация / ISR 🔴

**Цель:** маршруты `[locale]`, `[locale]/lp/[slug]`, `[locale]/quiz` и пр. перестают быть `ƒ`; главная — ISR, лендинги/квиз — статика.

**Изменения (по паттерну гайда Next 16 + next-intl static rendering):**
1. Перенести `<html>`, `<body>`, шрифты, `ThemeProvider`, `AnalyticsProvider`, inline-скрипт scrollRestoration и глобальную `metadata` из `src/app/layout.tsx` в `src/app/[locale]/layout.tsx`. `<html lang={locale}>` берёт локаль из параметра, **без `getLocale()`**.
2. Убрать `getLocale()`. Корневой `src/app/layout.tsx` и `src/app/page.tsx`: привести к санкционированной форме (корнем html/body становится `[locale]/layout`; `/` всё равно всегда редиректится прокси). Точную форму (pass-through root layout vs. удаление) подтвердить по `node_modules/next/dist/docs` перед правкой — AGENTS.md обязывает.
3. Проверить, что во всех страницах/layout перед вызовами next-intl API стоит `setRequestLocale(locale)` либо передаётся явная локаль (в `metadata.ts`/`generateMetadata` уже передаётся).

**G5 (специфика этапа):** в таблице `next build` локальные маршруты показывают `○`/ISR, а не `ƒ`. Главная — с `revalidate`. `/api/og` остаётся `ƒ` (edge) — это ок.

**Риски:** next-themes (FOUC-скрипт) и suppressHydrationWarning должны остаться высоко в дереве — после переноса в `[locale]/layout` это сохраняется. Проверить отсутствие двойного `<html>`.

## Этап 2 — Клиентский пейлоад словаря 🟡

**Цель:** в `NextIntlClientProvider` уходят только неймспейсы, нужные клиентским компонентам, а не весь словарь (ru 36 KB).

**Изменения:** определить набор неймспейсов, используемых в `"use client"`-компонентах (`enroll_form`, FAQ-UI, `LanguageSwitcher`, cookie-banner и т.п.), и передавать в провайдер только их (механизм — по next-intl docs v4: `pick`/scoped messages). Серверные компоненты продолжают использовать полный словарь на сервере.

**G5:** клиентские компоненты переводятся корректно во всех локалях (модалка, форма, FAQ, переключатель языка, cookie-баннер); в HTML-пейлоаде страницы нет полного словаря.

## Этап 3 — Вес бандла лендинга 🟠

**Цель:** First Load JS лендинга ≤ 80 KB gz; framer-motion вне пути лендинга.

**Изменения:**
1. `FadeIn` — заменить framer на CSS-анимацию + IntersectionObserver (тот же публичный API компонента), либо CSS scroll-driven. Цель — убрать framer из server→client графа лендинга.
2. `LandingFAQ` — нативный `<details>`/CSS-аккордеон (плюс к a11y), без framer.
3. `EnrollModal`/`EnrollForm` — грузить через `next/dynamic` (`ssr:false`), подгружать по клику на CTA, чтобы `react-hook-form`+`zod`+`@react-input/mask` не попадали в первичный JS.
4. Убрать дублирующий `<EnrollModal />` из `lp/[slug]/page.tsx` (оставить единственный — в layout).

**G5:** измеренный First Load JS лендинга (метод из Этапа 0) ≤ 80 KB gz; модалка открывается/закрывается по CTA, FAQ раскрывается, scroll-reveal работает; в чанках лендинга нет framer-motion.

## 📊 Baseline (Этап 0, до правок)

Сборка: Next 16.2.4 Turbopack. **Все** app-роуты = `ƒ (Dynamic)`, статики нет (подтверждает узел №1).

**Метод замера First Load JS** (эталон для всех этапов): `next build`, затем `next start -p 3137`, `curl` страницы, собрать все `<script src="/_next/static/chunks/*.js">` из HTML, просуммировать gzip соответствующих файлов на диске (`/_next/` → `.next/`).

Лендинг `/en/lp/no-friend` — **14 script-чанков ≈ 459 KB gzip** (бюджет §17 = 80 KB, т.е. ~5.7×). Крупнейшие:

| gzip | raw | что |
|---|---|---|
| 128 KB | 429 KB | posthog-js |
| 79 KB | 315 KB | zod |
| 69 KB | 221 KB | react / react-dom |
| 38+38+38 KB | — | vendor/shared |

Главная — ~459 KB (то же). Замер бандл-анализатором Next: `next build --experimental-analyze` → HTML-треемап в `.next/diagnostics/analyze/index.html`.

> Замечание для Этапа 4: posthog-js (128 KB) присутствует в чанках первой загрузки лендинга, хотя `import("posthog-js")` стоит за consent-гейтом — проверить, что код-сплит реально отделяет его, при правках аналитики.
